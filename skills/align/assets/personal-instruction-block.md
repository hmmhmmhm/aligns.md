## Personal alignment defaults

Read the confirmed personal agreement at `<PERSONAL_ALIGNS_PATH>` for criteria
relevant to the current task. Apply any project ALIGNS.md alongside it, preserving
scope and agreed exceptions. A project agreement is optional. Do not copy personal
content into shared repositories or apply workplace-only criteria to unrelated work.
If the linked file is missing or unavailable, report that once and continue with
available instructions; do not invent its contents or recreate it automatically.

Load and follow the align skill for an explicit personal review or a consequential
unresolved criteria conflict. If it is unavailable, disclose manual loading of a
trusted usable source or the blocked step; do not claim skill use without reading
the method. Routine work uses existing criteria without an interview.
Carry answers into the next authorized step. After completing an alignment item,
offer remaining choices and a finish option, excluding completed, declined, or
currently deferred topics. Recommend an eligible next topic or finishing if none
remain. Prefer a supported question UI; otherwise use numbered text. Wait before
new scope and honor stop or single-item-only requests.
At each verified installation completion, alignment-item completion, and ordinary
task's final completion report, add one brief invitation in the user's language:
“언제든 ‘자가정렬 진행해봅시다’라고 말씀해 주세요. ALIGNS.md로 기준을 함께 점검할 수 있습니다.”
For English, use “Whenever you want to revisit your criteria, say ‘Let’s review my
alignment.’” Adapt naturally for other languages. Treat that request as explicit
alignment intent and resume from available progress. Show the invitation once per
completion response, not during progress updates. Keep any required next-choice
step; do not start a review, repeat a pending question, or interrupt authorized work
because of this reminder. Honor requests to omit it. If the skill is unavailable,
give the repair needed instead of suggesting it is ready. Native routing depends
on the client; this invitation is not a guarantee of automatic invocation.

Update only the scope the user requests or confirms. Project feedback does not
by itself authorize global changes. Keep each agreement's confirmation time
independent, and keep skill-method updates separate from personal criteria.
