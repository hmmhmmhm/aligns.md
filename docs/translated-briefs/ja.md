# ALIGNS.mdでチーム向けコーディングエージェントの学習データを準備する

エンジニアリング責任者、モデル開発チーム、MLOpsチーム向けの導入検討資料です。

[English](../team-mlops-brief.md) · [한국어](ko.md) · **日本語** · [手動提出ガイド](../team-training-data.md) · [データ仕様](../../skills/align/references/team-training.md)

## 何を導入するのか

ALIGNS.mdを使うと、コードレビューやエージェントとの会話でチームが下した判断を残し、承認された事例をチームの学習実験に渡せます。たとえば、パッチの変更範囲が広すぎる理由を説明したレビューには、マージ済みのコードだけでは分からない情報があります。当時の文脈、修正内容、受け入れた結果を一緒に残すことで、その判断を後の学習に使えます。

最初は、一つのリポジトリや業務を対象にデータ収集を試すことを提案します。ALIGNS.mdが提供するのは、収集の手順、手動レビューの仕様、ローカルの書き出しツールです。データ、レビュアー、モデル、学習基盤はチームが管理します。スキルをインストールしても、オンラインの受付サービス、会話のバックグラウンド記録、モデル学習は始まりません。

**現在は、MLOpsチームが主体となってデータ収集を試す段階に対応しています。** テキストと選択したツール呼び出しの出力は、バージョンを固定した一つのトークナイザーで読み込みとトークン境界の検査を通過しました。実際のトレーナーへの接続とコーディング能力の向上は、これから測定する必要があります。この資料では、実装の検査結果とモデルの性能を分けて報告します。

## データとして残す価値があるもの

| 出典 | すでに含まれる情報 | ALIGNS.mdで追加して残す情報 |
| --- | --- | --- |
| エージェントとの会話 | 依頼、提案された回答、その後の修正 | 判断時点で利用できた文脈、学習対象への明示的な承認、適用する基準 |
| コードレビュー | パッチの議論と修正依頼 | その実装がチームに合う理由、受け入れたパッチと適用範囲 |
| CIやローカル検査 | テストコマンド、出力、失敗 | 基準コミット、実行環境、レビュー対象のコードに結び付いた証拠 |
| チームの現在の基準 | 合意した優先順位と制約 | 基準のバージョンと該当部分のスナップショット。古いルールを無意識に学習させないために使う |
| 初回から受け入れられた結果 | 修正のやり取りが少ない成果物 | 明示的な承認。修正会話だけに偏ったデータを避ける |

保守しやすい変更、APIの維持、適切なタイミングでの要件確認、実際に行った検査だけを報告する姿勢などが対象になります。実装を学習させるには、受け入れたパッチや行動を収集します。「変更範囲を絞ります」という回答は応答スタイルの例にはなりますが、その変更を実装できた証拠にはなりません。

チームの基準は明示的な合意が必要です。頻出するコメントや一人のメンテナーの好みを、そのままチームの正解ラベルにはしません。個人の合意は別に扱います。

## 出力ファイルと用途

| ファイル | 内容 | 用途 | 注意点 |
| --- | --- | --- | --- |
| `sft-completion.jsonl` | プロンプトと、選択した一つのアシスタント出力 | テキストの判断、コードパッチ、選択したツール呼び出しのSFT | completion-only lossを設定し、実際のトレーナーのマスクを確認する |
| `dpo.jsonl` | 同じ文脈のプロンプト、採用したテキスト、退けたテキスト | 選好最適化 | 人が承認した比較が必要。ツール呼び出しのDPOは対象外 |
| `evaluation.jsonl` | 学習用から分離したタスク群と期待する回答 | チームの評価基準による採点や実行評価 | 期待する文章だけではコードの正しさを評価できない |
| `manifest.json` | 出典、ハッシュ、レビュー、除外、件数、学習種別 | データの来歴確認と監査 | 非公開のメタデータ。トレーナーには入力しない |
| 従来の `sft.jsonl` | 選択した回答を末尾に加えたテキスト会話 | 既存のテキスト処理系 | 過去のアシスタント発言も残る。通常は選択した出力を分離したファイルを使う |

形式は[TRLのデータセット仕様](https://huggingface.co/docs/trl/dataset_formats)に対応しています。プロンプトと学習対象の出力を分けると、過去の誤答を文脈に残しつつ、選択した学習対象から外せます。学習側の設定も必要です。[TRLのcompletion-only loss](https://huggingface.co/docs/trl/sft_trainer#train-on-completion-only)を参照してください。

ツール呼び出しのレコードには、関数スキーマ、観測できた呼び出しと結果、選択した一つのアシスタントの行動を残します。書き出しツールは呼び出しの対応関係と関数名を検証しますが、JSON Schemaの引数制約をすべて検証したり、エージェントの実行全体を再現したりはしません。実行全体の軌跡やモデル固有のrole・channel形式には、アダプターが必要です。

## バージョン0.11.0で実装した検査

[初期監査](../training-data-readiness.md)で、従来のテキスト出力に不足が見つかりました。今回の変更では再現できた問題に対処し、チームからの提出を扱う手順を加えました。提出された承認記録は確認すべき証拠であり、レビュアーの本人性を暗号学的に証明するものではありません。

| 項目 | 初期状態 | 現在の実装 | チーム側で必要な対応 |
| --- | --- | --- | --- |
| チームの承認 | 手動の案内のみ | 許可レビュアーのポリシー、対象・ペアの明示的承認、レビュー参照、バージョンと日時の検査 | ポリシーの管理とチーム基盤での本人確認 |
| ファイルの完全性 | 出典への参照 | 提出ファイルのバイト列ハッシュ、正規化したレコードのハッシュ、証拠ファイルと出力のハッシュ | ストレージの保護と原本の保持 |
| 文脈 | 学習入力の外にしか存在しない場合があった | バージョン2ではプロンプトの抜粋と、確認済み入力スナップショットのダイジェストが必須 | 内容が十分かを確認し、判断後に判明した情報の混入を防ぐ |
| 学習対象 | 過去のアシスタント回答もSFT会話に残った | プロンプトと学習対象の出力を分離 | トレーナーのラベルと文脈の切り詰めを確認 |
| 矛盾する比較 | 逆向きのラベルも両方出力できた | 同じ文脈・基準で選好の有向サイクルを検出し拒否 | 意味上の矛盾や文脈をまたぐ矛盾をレビューで解決 |
| コードの証拠 | 自由記述の検証情報 | 基準コミット、対象に含まれるパッチ、成功した検査の記録、ハッシュ付きの証拠を必須化 | 制限した環境で再実行し、テスト範囲を評価 |
| ツール | テキスト専用の出力では拒否 | 関数スキーマ、対応する呼び出しと結果、選択した行動の出力 | ツールスキーマと選択したモデルの挙動を確認 |
| データ分割 | ユーザー指定のタスク群とプロンプトの完全一致検査 | バッチをまたぐ共通のタスク群割り当て、完全一致の拒否、名前空間付きID | 割り当て前に関連タスクと意味上の重複を検出 |
| 撤回 | 手動の案内 | ポリシーで名前空間付きレコードを除外 | 影響を受ける既存データセットと学習済みモデルを特定 |
| 無効な提出 | 目視確認 | 書き込み前の検証、上書き禁止、読み取り専用の検証モード | 承認を捏造せずに不備を修正 |

検証処理は、提出コードの実行、モデルのダウンロード、レコードのアップロード、学習開始を行いません。コードの証拠を調べる処理は、必要な証拠が申告どおりに存在し、変更されていないことを確認します。テストが実際に実行されたかを独立して証明するものではありません。

## 過去のベンチマークで分かること

既存の[確認済みの好みを保持する予備実験](../../RETENTION_BENCHMARK.md)は、基準を残す効果を調べる動機になります。ファインチューニングの実験ではありません。

| 各条件で合成タスク12件を実施 | 一般的な指示、学習・保存は可能 | 確認済みの好みを初期入力し、alignを使用 |
| --- | ---: | ---: |
| 確認の回答なしで好みに合った件数 | 3 / 12 | 12 / 12 |
| その後の確認に対する回答数 | 9 | 0 |
| 最終的に好みに合った件数 | 12 / 12 | 12 / 12 |

初期入力がある条件には、比較側が最初には持っていなかった情報に加え、スキルと参照手順も与えています。初期設定に必要な回答は、別途4回と仮定しました。ファイル名だけの効果や、同じ情報を持つAGENTS.mdに対する優位性を示すものではなく、人が費やした時間も測っていません。[情報量をそろえた比較](../../DISCOVERY_BENCHMARK.md)では同じ結果でした。

これらの結果を踏まえ、対象を限定した作業で、確認済みの基準を保持すれば説明の繰り返しが減るかを検証できます。ファインチューニングの改善率、学習データの価値、投資収益には換算できません。

## 試験導入の手順と担当

| 段階 | 担当 | 成果物 | 完了条件 |
| --- | --- | --- | --- |
| 範囲の決定 | エンジニアリング責任者と参加者 | 一つの業務、合意した基準、許可する出典、非公開の保存先 | 参加者が収集内容と用途を理解している |
| 記録 | 参加に同意した人とエージェント | 作業中または選択した履歴からの小さな候補レコード | 実際の文脈、対象、利用できる証拠を保持している |
| 手動の提出確認 | 参加者 | 選択したバッチとファイル一覧 | 提出するファイルそのものが、指定用途について承認されている |
| レビュー | 指定されたチームのレビュアー | 対象・ペアに結び付いた判断と共通のタスク群 | 未解決のラベルを学習データにしない |
| 検証・書き出し | MLOps | バージョン付きデータとマニフェスト | 仕様検査に合格し、除外内容を確認している |
| 学習基盤への接続 | MLOps | 固定したトークナイザーとトレーナー、collator検査、許可された試験学習 | マスクが正しく、切り詰めで対象を失わず、実行を再現できる |
| 評価 | エンジニアリングのレビュアーとMLOps | 学習から分離したデータでの評価と回帰の報告 | 学習前に合意した基準を満たす |

週次やスプリント単位の提出も選べますが、頻度はチームが決めます。意味のある判断時点で記録し、既存の承認を再利用して、不足しているラベルだけを確認します。最終提出は手動です。一人あたりのレコード数のノルマは設けません。

## 件数だけでなく、使えるデータを測る

| 指標 | 定義 | 判断に使う点 |
| --- | --- | --- |
| 承認率 | 承認された重複のない例 / レビューした候補 | 関連する事例を収集できているか |
| レビュー効率 | 承認された重複のない例 / レビュアーの作業時間 | 手間が減ったのか、別工程に移っただけなのか |
| タスクの網羅性 | 基準・業務・難易度別の異なるタスク群 | 追加の証拠が必要な領域 |
| 証拠の充足率 | 再実行に必要な資料があるコード候補 / コード候補 | コーディング事例を検証できるか |
| DPO適格率 | 承認された同一文脈のペア / レビューした比較 | 選好最適化に使えるデータがあるか |
| 重複率・矛盾率 | 該当するレコード / レビューしたレコード。別々に報告 | 水増しやラベルの不一致がないか |
| 評価の独立性 | 関連する学習タスクが知られていない評価用タスク群 | 汎化を評価できているか |
| 学習後の修正負担 | 評価タスクごとのレビュアー介入数。コードの正しさと併記 | チームの実務が改善したか |

しきい値は試験導入の費用と目的から決めます。一定件数が集まっただけでは、学習の準備ができたとは判断できません。生成した派生例は、把握している網羅性の不足を補うために使い、元のタスクとの関係を残し、別のラベルで区別します。言い換えを独立した証拠として数えないようにします。

## 導入前にモデルを評価する

同じベースモデルとALIGNS.mdを使う条件を、チューニング後のモデルに同じALIGNS.md、ツール、タスク予算を与える条件と比較します。派生例を作る前にタスク群を固定します。検証結果をチェックポイントの選択に使う場合は、最終テストセットを別に確保します。正しさ、不要な質問、範囲の判断、完了報告、レビュアーによる修正を確認し、一般的なコーディング課題や変更されたばかりの基準でも回帰を調べます。

不確実性はタスク群の単位で報告します。修正回数が減ってもコードの品質が落ちたなら成功とはいえません。リポジトリの現在の事実や更新した基準は、引き続き実行時の文脈に入れる必要がある場合があります。ALIGNS.mdを変更しても、学習済みの挙動が自動更新されるわけではありません。

## 導入の範囲

収集・書き出しの実装は、このリポジトリのMITライセンスで利用できます。このライセンスは、参加者のコード、会話、第三者の資料を使う権利までは与えません。学習用途、保持期間、利用するサービスはチームが決めます。非公開の出典参照とマニフェストも、選択したレコードと同様に扱う必要があります。

最初は範囲を限定したデータ収集を試し、その後にモデル固有の接続を確認する進め方を提案します。レビュアー認証の自動化、意味上の矛盾の解決、制限した環境でのコード再実行、オンライン受付、本番での効果測定は、現在の実装に含まれていません。導入の判断はチームが行い、ALIGNS.mdの合意内容を変えずに収集を停止できます。
